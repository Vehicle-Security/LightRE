# V0.2：自动初次还原与人工反馈

状态：2026-11-01 已通过用户人工验收，用户授权提交 GitHub。DG 核心巨函数 `0x1c07c` 尚无 C 候选，按用户决定留到后续差分阶段处理；其余已知限制和实跑记录见 [DELIVERY.md](DELIVERY.md)。

## 核心验收标准

本版按最新反馈限定为 **Ghidra 直接反编译 + 一轮 LLM 保守整理**。允许保留控制流平坦化、goto、MBA 表达式、间接调用和 Ghidra 类型，不要求恢复 VM 操作码语义、去混淆或去虚拟化；这些分析留到后续版本。Ghidra 警告或缺失路径必须随候选记录，不伪造缺失代码；既无可用伪代码也无已有候选时，在同一首轮任务内自动使用完整汇编输入，不用占位代码凑覆盖率。

用户也可显式选择已有工作区的 **纯汇编 LLM 模式**（input_mode=assembly）：不加载 Ghidra 参考伪代码、不写 Ghidra 初稿、不调用 Ghidra，将全部已保存指令和地址一次性内嵌到初始提示词，同时保存带机器码的快照，并允许用原 ELF 与 objdump 补核边界和指令。它沿用一轮候选及队列机制，允许保留混淆结构；未形成候选时仍如实记录。已有函数目录及汇编可复用历史 Ghidra 静态导出，不表示已实现全新的无 Ghidra 二进制导入器。

稳定、快速地让两个样本的全部已识别函数得到有依据的 LLM 初步候选，无需人工逐个发起。已有候选可复用，剩余函数自动批处理；要求从头验收时必须明确是否复用。无法恢复的函数保留具体未解决结论和后续方向，这是缺口记录，不能据此宣告“全部函数已还原”。验收核对真实 batch 输出和复用来源，不能仅凭候选文件或知识章节存在认定已调用模型。CLI 执行失败单独统计并修复，不能算作模型已分析，也不能以任务启动或处理计数代替全量完成。记录静态导出、模型处理和必要恢复的实际耗时、候选数、未解决数和执行失败数；最终由用户人工验收。

首轮使用准备好的 Ghidra 初稿、当前候选和逐函数知识，短函数附完整汇编；既无初稿也无已有候选时自动改用完整汇编快照、保留读取工具及本机推理配置，按每批 600 秒执行；两类输入分别合批，不因缺少 Ghidra 伪代码仅提供首尾片段。首轮优先返回针对输入原文的局部修改；LightRE 用批次输入快照校验并应用修改，避免重复生成大段未改代码。模型可明确审阅后保留初稿及其警告并记录疑点；这计为 LLM 已处理，不表示该函数已经完成去混淆。有初稿的首轮批次不逐函数调查或调用工具，新建任务不自动追加深入去混淆任务；用户仍可用评论要求继续调查。完整汇编始终保存在 workspace；有初稿的超大函数仍以伪代码为主，纯汇编批次则直接内嵌全部已保存指令。

## 本轮范围

1. Ghidra Headless 自身枚举函数并统一导出范围、完整汇编、分组与参考伪代码，由 LightRE 自动整理模块初稿，再循环调用 Codex CLI 结合参考与汇编还原；单函数反编译失败保留汇编与原因，整体导出失败不发布目录。随后后台自动调用本地 `codex exec`，按同模块每批最多 4,000 条汇编指令、32 个函数及 60,000 字符参考代码与知识打包，默认 8 批并发尝试全部尚无 LLM 候选的函数；超大函数独立处理，完整汇编保留在 workspace。Web 可立即打开，不等待全量还原。
2. 每个函数保存一份当前 C 候选片段，按 Ghidra 分组组合到 `source/src/<模块>.c`，每文件最多 20 个函数。Web 按 RVA 显示同一源码片段，SQLite 仅维护派生路径索引。自动加 `@lightre.begin/end` JSON 标记，保存 ID 与 origins，不重复写 SO 名称、哈希和状态；Web 隐藏机器注释，普通注释和代码正文保留。无法还原时保存原因，不生成占位代码。
3. 每个 SO 用一份 `knowledge.md` 保存 Markdown 分析上下文，按函数 RVA 二级标题分节，通过 API 按函数读取和更新；旧逐函数知识文件合并校验后移除。任务、模型输出和日志落在当前 SO 的目录，新会话可以继续。
4. Web 显示候选生成进度和逐函数状态，支持状态筛选、任务队列、暂停、继续及单任务取消。进度变化后自动读取选中函数，保留用户评论草稿。
5. 人工可提交修改建议启动该函数下一轮分析，无需逐个认可；建议保留提交时的代码快照和内容摘要。同一 SO 使用持久任务队列；评论可在忙碌时提交，优先调度，同优先级 FIFO，批量任务在批次之间让位。
6. 新建任务完成一轮后停止，模型未解决和执行失败分别记录；不以自动深入去混淆为本版前置。旧任务显式保存的 auto_refine=true 仍按原策略续跑，保留父子任务及各自输出，不改写历史。

内部能力收在 `src/recovery/`，只保留分析和 Web 的外层启动入口。模块整理属于工具功能，不能靠交互 Agent 临时搬文件；初稿不覆盖已有 LLM 工作，合并不修改函数正文或内容摘要。Ghidra 分组不承诺恢复原始源码模块。沿用一对一函数 RVA，使用本地任务文件和文件锁，不增加每轮候选历史、队列服务或独立缓存层；只有显式重导出改变边界时归档旧结果，避免旧代码继续冒充适用当前边界。

## 人工验收

1. 用两个既有启动 Markdown 中的一个分析样本，看到汇编后，无需逐个指定函数即可看到候选进度。
2. 对照一个短函数的汇编和候选；Web 的代码和普通注释与 `source/src/` 片段一致，仅隐藏机器注释；原始 code 和冲突摘要仍取文件片段；旧小文件无损迁移且移除。
3. 页面不提供逐函数认可按钮；可提交重命名、类型或逻辑修改建议。页面代码过期时拒绝提交并保留草稿。
4. 全量分析运行时连续提交评论，确认本地 `task.md`、提交时快照和独立 state.json 保留；队列显示等待，评论优先执行后继续全量任务，Web 自动展示新候选与上下文。
5. 等待首轮结束，核对总数、LLM 候选、模型未解决和执行失败；记录实际耗时。旧任务如有 followup_id，也跟踪至终态。无伪代码或无模型结果时保留原因，不计为候选覆盖；候选中保留混淆结构或已注明的 Ghidra 警告，不作为本版去混淆验收失败。429 自动降低后续并发，单批超时或输出缺项不取消其他健康批次。有初稿的快速首轮每批 180 秒、汇编及评论/定向批次每批 600 秒，每函数执行失败最多额外重试 1 次；缺项只重试缺项。暂停续跑优先发布已保存的有效输出，跳过已确认完成函数；未保存或无法确认输出的批次可能重跑，不承诺严格只执行一次。
6. 修改、移动或删除模块内函数后，源码索引同步重建，无重复或残留行；更改其他函数不影响当前函数的内容摘要。直接编辑后重新读取可见；当前自动刷新由任务进度驱动，尚无统一发布 revision。
7. 暂停后已有结果与排队评论保留；继续时跳过已有 LLM 候选，Ghidra 初稿仍需处理。重启 Web 不影响后台任务。

以代码审阅和界面人工查看为主；自动检查只覆盖关键数据行为，不增加浏览器套件。

## 边界

候选生成或未收到修改建议均不表示等价验证，不要求人工逐函数认可。此处记录 V0.2 验收边界；后续 V0.31 已加入原函数单边运行，候选差分仍待实现。本轮不实现无限自动重试、函数合并/拆分、完整源码工程或跨版本知识共享。
