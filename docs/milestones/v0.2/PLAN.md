# V0.2：展示单函数还原候选

状态：用户已确认范围，尚未实现。本次只记录计划；当前可运行版本仍为 [V0.1](../v0.1/DELIVERY.md)。

## 目标

打通一个函数的最小反馈闭环：读取已保存的汇编 → Agent 理解并编写候选 C 代码 → 保存文件 → Web 查看 → 人工反馈 → Agent 修改 → 刷新查看。

先选择一个约 10–50 条指令、逻辑清楚的函数。只交付这个可运行、可人工验证的小增量。

## 三项功能

| 功能 | 最小行为 | 验收方式 |
| --- | --- | --- |
| 保存候选 | Agent 从现有 workspace 读取目标函数汇编，生成可读 C 候选，保存在当前 SO 的分析目录；注释记录 binary 文件名、SHA256、原始函数 RVA，标明“分析候选，未验证” | 文件存在，来源对应当前 SO 和函数；重新进入会话仍可读取 |
| 展示候选 | 右侧增加“还原代码”页签，与原始汇编切换；直接读取保存的同一份文件，没有候选时显示“尚未还原” | 页面正文与文件一致；其他函数仍可正常浏览汇编 |
| 地址关联 | 用当前 SO 结果目录和函数 RVA 定位一份当前候选；沿用 SQLite 的原始函数索引，候选正文只存文件 | 打开函数读取对应候选，不与其他 SO 的同 RVA 混用；手动修改候选后刷新即可更新 |

文件路径规范在开发时选择最简单的一种并固定，不为本轮引入完整源码索引、候选历史或新的身份系统。当前先保持一份候选对应一个原始函数；函数合并、拆分和版本发布到真实需要时再增量设计。

## 实现顺序

1. 提供最少的保存、读取能力，让 Agent 能把一个函数的候选写入当前 SO 目录，并在新会话读回。
2. Web 增加候选读取和页签切换，保留 V0.1 的函数列表与原始汇编浏览。
3. 更新 Skill，按实际能力说明如何生成候选、保存并打开页面；用一个短函数走完人工反馈与修改。

每一步都保持已有工具可运行。候选由当前 Agent 编写，Web 只读文件，使用手动刷新。

## 人工验收

1. 从 dg 或 minilua 的现有结果中，选一个约 10–50 条指令的清楚函数，记录所选 SO 和 RVA。
2. Agent 读取汇编，保存带来源注释的候选 C 代码。
3. 页面选中该函数，切换“汇编 / 还原代码”，对照检查地址和逻辑。
4. 人工提出一条具体意见，Agent 修改同一候选文件，刷新后看到更新后的原文。
5. 另一个没有候选的函数显示“尚未还原”，汇编浏览仍正常。
6. 重启 Web 或换 Agent 会话后，仍能读到保存的候选。

以人工审阅代码和界面为主；必要时仅对文件读写与地址关联补快速测试，不增加浏览器验收套件。

## 本轮边界

候选是未经执行验证的分析结果，不宣称与原函数等价。本轮不要求批量反编译、Web 启动 LLM、自动多轮迭代、Ghidra 接入、unidbg、Evidence 库、函数差分或候选编译运行。

后续按反馈单独推进“一次 unidbg 原函数运行并保存 Evidence”，再逐步加入候选执行与差分验证；本计划不授权自动开发这些后续能力。
