## 当前实现

- **纯汇编模型输入**：`src/recovery/assembly.py` 将全部已保存指令、地址和知识直接内嵌到初始提示词，并保留带机器码的任务快照；`scripts/analyze.py <SO分析目录> --input-mode assembly --rva <RVA>` 可直接调用模型，不加载 Ghidra 伪代码、不生成 Ghidra 初稿或启动 Ghidra。模型保留 shell/Python/objdump 补核能力，按 600 秒一批处理；结果仍走原队列、格式化、发布与知识接口。默认首轮对既无初稿也无已有候选的函数自动使用此输入。既有目录和汇编可来自历史 Ghidra 导出，未实现新二进制的无 Ghidra 导入器。当前轻量检查 90 项通过，实际模型结果及输入限制见上方实跑记录。
- **静态导出**：`src/analyzers/ghidra.py` 与 `ghidra_scripts/ExportReferences.java` 由 Ghidra 自身枚举函数，统一导出范围、完整汇编、模块分组及参考伪代码；单函数失败保留原因和汇编，整体失败不发布不完整目录。默认自动分析/单函数限时为 300/60 秒。Rizin 仅用于按需查询。
- **模块与源码**：`src/recovery/source.py` 自动写入初稿并按模块整理，通常每文件最多 20 个函数，保留共享声明和已有 LLM 代码。`candidates.py` 保存当前片段及派生索引；Web 读同一份代码，不保存正文副本。
- **结构化标记**：`markers.py` 处理 `@lightre.begin/end` JSON 注释，保留 SO 内稳定 ID 和单 RVA origins，跳过源码字符串和普通注释中的示例，校验配对与重复。旧格式仍可读，保存目标函数时转换；显式全目录转换须在任务空闲时执行。`display_code` 隐藏机器注释，`code`、冲突摘要和任务快照仍取原始片段。
- **快速首轮**：`jobs.py` 默认 8 批并发，同模块按最多 4,000 条指令、32 个函数、60,000 字符参考代码与知识打包；单个超预算函数独立处理。模型直接接收上下文、使用 low 推理并关闭调查工具，优先返回局部原文修改，由 LightRE 对批次输入快照校验并应用。
- **失败与恢复**：单批 CLI 错误、输入管道断开、超时或无效输出不取消其他健康批次；有效子集先发布，缺项最多额外重试一次，429 降低后续并发。首轮批次 180 秒，评论/定向 600 秒。已保存输出可在续跑时校验并发布；源码损坏、来源或存储错误仍中止任务。执行失败与模型未解决分开记录。
- **续做兼容**：新任务仅执行一轮；旧任务显式保存 auto_refine=true 时，仍为模型未解决项安排一次定向任务，以 followup_id / parent_task 关联，不递归追加。评论保留主动续做能力。
- **持久队列**：`queue.py` 使用 `tasks/<id>/` 文件及本地锁，评论优先、同级 FIFO、批次之间让位、活动请求去重，支持暂停/继续和单任务取消。`_worker.py` 在后台运行，队列清空后退出。关闭 Web 不停止 worker；Web 启动可恢复已有且未暂停的队列，不创建新分析任务。
- **知识**：`knowledge.py` 用每 SO 一个 `knowledge.md` 按 RVA 分节，进程内复用解析结果，文件变化时重载，每批至多原子写一次。旧单函数知识校验迁移后移除，冲突保留资料。
- **Web**：`src/webui/` 提供函数名称/RVA 搜索、LINES 排序、紧凑可调左栏、明暗主题、汇编自动分页、源码/汇编并列及比例拖动、状态筛选、任务队列和评论续做。任务进度驱动自动刷新，保留评论草稿；不要求逐函数人工认可。
- **入口与环境**：`scripts/analyze.py` 先导出再启动首轮，`scripts/web.py` 浏览已有结果，没有独立 candidate/recovery CLI。Skill 固定调用目录、显式传外部 workspace，并在分析前准备 Python 依赖；工具与样本仓库不存放分析结果。

SQLite 当前保存 metadata、functions、assembly 和可重建的 `source_index(function_rva, path)`；任务状态在 JSON，知识和源码正文在文件。不同 SO 分别维护。没有接入 MCP、常驻队列服务或共享正文缓存层；源码解析和知识的进程内复用不增加持久副本。
