# V0.2 交付记录：单函数候选展示

状态：已实现，等待用户在新电脑 clone 后人工验收。范围以 [PLAN.md](PLAN.md) 为准，操作见 [USAGE.md](USAGE.md)。

## 实现

- `src/candidates.py`：按当前 SO 目录和函数 RVA 保存、读取一份当前 C 候选，自动添加来源和未验证注释；文件原子替换，来源不符会拒绝。
- `scripts/candidate.py`：独立的 `save` / `read` 入口，可从任意目录使用，无需 Web 或分析工具。
- Web 增加“还原代码”页签和只读候选接口，直接显示实际文件原文及路径；无候选显示“尚未还原”。文本按纯文本插入页面。
- URL 保留视图和函数 RVA，手动刷新、重启或新会话仍可读取；切换函数时取消旧请求，避免显示另一函数的返回结果。
- SQLite 无新增正文、映射表或格式迁移，沿用 V0.1 数据；其函数搜索、行数排序、浅深主题、紧凑布局、拖动左栏和汇编滚动分页保留。
- Skill 增加候选编写、保存、修改和打开说明。`--rizin-only` 支持仅安装当前需要的分析依赖，跳过 Ghidra / Java。

## 真实最小例子

仓库小函数版 minilua 的 `0x23314`，15 条指令。根据实际保存的汇编编写 [候选文件](../../../samples/minilua/candidates/0x00023314.c)：读取 context + 0x20 的指针，反复检查其 + 0x50 字段，非空时调用 `0xab94`，每轮重新读取指针和字段。

`runtime`、`pending` 是暂定名称，不声称恢复了业务语义；候选未经执行等价验证。原始二进制和示例候选均随仓库保存，可由 [minilua_start.md](../../../tests/minilua_start.md) 在新机器创建外部 workspace 并导入。示例只匹配小函数版的 SHA256，不复用到其他版本。

## 边界

候选由当前 Agent 生成与修改，页面只负责读取。暂不提供自动批量还原、自动迭代、候选历史、函数合并/拆分、unidbg、Evidence 库、差分验证或 Web 评论。
