# V0.31 计划：最小 unidbg harness 与任务循环

状态：按用户反馈从 V0.3 总体方案中拆出的首个小版本，尚未开发或验收；V0.2 已于 2026-11-01 单独通过用户人工验收。本次范围复核将最小任务循环提前加入本版，用于 harness 的运行与修复；总体方向见 [V0.3](../v0.3/PLAN.md)。

## 用户结果

提供一个 Android ARM64 测试 SO 和明确的输入，LightRE 通过最小 unidbg harness 调用已知导出函数，保存返回值、指定输出缓冲区及运行资料；新进程可以按保存材料重放。

同一任务可由 Python 多轮调用 Codex 调整 harness：每轮原样保存返回正文及日志，由外层实际运行并检查结果；未通过时，下一轮读取上轮结果和检查记录继续，直到满足当前任务或保存明确的停止原因。本版验证的是 harness 能正确调用测试库，不包含恢复候选的构建、双边差分或业务等价验证。

首个目标使用几十行 C 的专用测试库，无 JNI、无 VM、无混淆和复杂初始化。测试库包含整数运算和输入/输出缓冲区操作，结果可直接核对。它只验证 harness 基础能力，不能当作 DG、minilua 或 VM 已运行的证据。

## 输入来源

两套 VM 的输入约定已明确：DG 使用配套样本 `bytecode/libdC6BDAE49562F.so/` 下现有的 4 份 `.bin`；minilua 使用仓库内的 `.lua` 用例，由自身解析器生成内部字节码并执行，复用已有预期输出。后续真实目标适配优先使用这些现成输入，不以开发字节码生成器、外部 luac 加载器或 fuzz 为前置。目前尚未验证它们在 unidbg 中的加载和运行。

本版先支持用例引用一个输入文件，由 harness 读取字节，在模拟器中分配缓冲区并按测试函数签名传入地址和长度，读回声明输出；实际输入内容与来源随 Run 固定。简单用例仍可直接填写字节或整数。读取文件与构造参数按本样本编写普通代码，不增加通用输入配置语言。该能力支持后续接入已有字节码，但将文件字节传给测试函数不代表真实 VM 已执行。真实 VM 适配时再确认资源对应的 SO、加载入口、附带参数、初始化和结果提取方式，从一份种子开始，跑通后重放其余种子。

## 本版开发内容

| 内容 | 最小范围 |
| --- | --- |
| 可用环境 | 固定实际 unidbg 版本，提供 Java/Maven 环境与启动说明，选定一个可用执行后端 |
| 测试 SO | 提供小型 C 源码与 Android ARM64 构建命令，记录工具链与产物依据；只为准备测试库，不做候选编译系统 |
| Java harness | 加载指定 SO，按已知导出符号调用；支持本样本需要的整数、指针、长度参数、整数返回及缓冲区读写 |
| LightRE 调用 | 提供一个轻量 Python 调用入口，传入目标与输入、启动 Java、收集结果和日志；供单次运行和任务循环复用 |
| 运行记录 | 每次运行在所选 SO 分析目录下保存独立 Run，记录实际 SO、输入、harness、命令、版本、退出码与观察结果 |
| 重放 | 用保存的 harness、参数和输入重新构建/运行，不依赖原进程或聊天上下文 |
| 最小任务循环 | 每轮独立调用 Codex，完整保存结果，将上轮报告与真实检查反馈给下一轮；以固定测试库的调用结果决定是否通过 |

Java 先按测试函数的明确签名编写普通调用代码，不建设任意 ABI 的通用调用器，不要求支持任意 RVA、JNI 对象、复杂结构体或任意 SO。Python 负责进程调用、记录及固定用例核验；缺少文件、Java/Maven 编译失败、执行失败或超时均保留具体错误，不能生成成功结果。不接 Web、后台调度平台或多 Agent 系统。

## 保存与复用

沿用既有 harness 目录约定：可编辑工程放在外部 `workspace/harnesses/<name>/`；当前 SO 的 `harness.json` 保存关联和所需参数；运行前将实际源码、pom、参数及输入的小型副本保存到 `runs/<run_id>/` 并从该副本执行。日志与结果保存在同一 Run。SO 和依赖按可保留的路径与内容依据引用，旧 Run 不默默加载被替换的文件。

LightRE 仓库可保存最小示例源码/模板与使用说明，用户目标的 harness、编译输出和运行产物保存在外部 workspace。不复制 Maven 缓存，不建设 harness 注册库、完整 Evidence 检索系统或多后端抽象；本版记录按未来差分可引用的方式保存即可。

## 本版的最小 loop

复用 [Goal Loop 的结果保存约定](../../GOAL_LOOP.md#最小落地先完整保存返回正文)，只实现当前 harness 任务需要的部分：

1. 任务约定可编辑的 harness 工程、目标 SO、固定用例、已知预期和检查方式。测试 SO、用例预期及外部检查器作为基准，不由模型修改来取得通过；测试库编译是预先准备步骤。
2. 开始或恢复时先检查当前 harness；已满足任务则直接保存依据。未通过时，在新的轮次目录准备原始任务、授权路径、上轮结果及最新实际错误的引用。
3. 每轮使用独立 `codex exec --ephemeral` 调整 harness。保存 `prompt.md`、完整 `result.md`、`events.jsonl`、`stderr.log` 和程序填写的 `execution.json`；初版不强制结构化返回、不提取摘要、不依赖 session resume。
4. 确认本轮及相关写入结束后，外层重新构建并运行实际 harness，核对测试 SO 的整数返回值和指定缓冲区结果，保存 `verification.json` 与 Run 引用。不能只检查 CLI 退出码、模型声明或日志中的“成功”。
5. 未通过时自动继续。下一轮读取上轮完整返回、执行情况及检查报告，核对当前文件，调整失败做法；需要时再读取更早记录，不把所有正文无限追加到 prompt。
6. 当前任务的 `state.json` 由执行器维护轮次、最新记录引用和停止原因，支持从保存记录继续。同一目标和 harness 保持单一写入者；取消或调用方指定限制到达时，结束在途进程、保留文件和未完成项。基础设施故障按有限重试策略处理，缺少必要资源时保存具体继续条件，不能空转或标成完成。

此循环直接服务于“让测试 SO 的 harness 跑通”。已知预期只检查 harness 基础能力，不代表通用差分或 VM 语义恢复。初版不做自动记忆提炼、会话恢复策略、通用任务框架或全工程恢复调度，也不修改 V0.2 只读单轮批处理的协议。

## 开发顺序

1. 先用普通 Java 工程跑通测试 SO：整数调用，再验证缓冲区传入、修改与读回。
2. 接入 Python 启动与结果收集，保存一次运行的输入、harness 和日志。
3. 从已保存 Run 在新进程重放，补齐必要的失败处理和使用说明。
4. 将已有运行入口接入最小任务循环，增加每轮原文保存、失败交接和实际通过判断，用有错误的 harness 草稿验证修复流程。

以上是同一小版本的实施步骤，不增加人工逐步批准环节，也不要求先开发完整任务系统。

## 验收

1. 对测试库执行整数用例和缓冲区用例，真实返回值、有效输出长度与内容符合已知预期；仅加载 SO 成功不算通过。
2. 改变输入后产生对应结果；新进程重放同一用例，结果一致，输出不依赖遗留模拟器状态。
3. 修改当前可编辑 harness 后，仍能用旧 Run 保存的副本重放旧实验。
4. 错误路径、缺失导出或执行故障能报告具体原因并保留日志；没有结果、超时或异常退出保持失败。
5. 按说明能够从测试源码准备 SO 并完成上述运行。测试源码构建和 Java harness 构建分别记录，不能混作恢复候选已可编译。
6. 有错误的 harness 草稿能够交给 Codex 调整，外层实际检查结果决定是否续跑。若某轮报告“完成”但检查失败，自动进入下一轮，输入包含上轮原文与具体失败；测试库、固定预期及检查器保持不变。
7. 每次尝试有独立轮次目录。CLI 异常、最终回复缺失或检查器失败保留日志与当前文件，不能沿用旧通过；取消后从记录核对当前内容继续，不并发启动两个写入者。

使用少量快速检查验证 Python 的结果收集和失败交接，可模拟 CLI 返回来检查“声称完成但检查失败”会续跑，不能 mock 掉被验证的记录与判定逻辑。真实 unidbg 运行和一次真实 Codex harness 修复单独记录；模拟结果不替代真实集成检查。不要求浏览器或完整 Web 测试。

## 后移内容

- **DG harness**：单独选择一个入口，调查并补齐实际需要的 JNI、Java 对象与环境。可调查已有 runner，但不作为本版通过条件。
- **minilua 适配**：单独增加薄 C 接口并构建 Android ARM64 SO，先跑无混淆版本，再考虑混淆版本；保留已有 Linux 样本。
- **差分与候选构建**：后续接入双边运行、函数级观察比较及候选 SO 构建。
- **差分驱动修复与探索**：在本版 loop 上接入候选语义差异与累计反例，再增加 fuzz、强制执行及 VM 检查点；本版只修 harness。

后续先选 DG 或 minilua 中一个目标适配，不把两者同时作为下一小步的必交付内容；具体后续版本编号另定。V0.31 通过只代表纯 native harness 和该范围的结果传承/修复循环可用，不自动勾选完整的动态差分、VM 恢复或工程自动修复需求。
