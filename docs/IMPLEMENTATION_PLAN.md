# LightRE 小步实现计划

本文规划交付步骤。当前提交基线为 V0.1，本轮人工验收反馈已落实；最终实现和现场记录以 [V0.1 milestone](milestones/v0.1/DELIVERY.md) 为准。V0.2 已确认范围但尚未实现，见 [V0.2 milestone 计划](milestones/v0.2/PLAN.md)。代码调整和开发自测不推进产品版本。长期方向见 [设计文档](LLM_DECOMPILER_DESIGN.md)，功能需求见 [需求清单](REQUIREMENTS.md)。

当前可运行基线为 V0.1；下一步按已确认的 V0.2 范围小步开发，其余增量按反馈选择。Workspace 是外层分析根目录，每份 SO 使用自己的分析子目录、SQLite 与知识，具体约定见设计文档的“开发基线”。

## 交付原则

每次只完成一个能实际运行、能由人工验证的小增量。先把函数显示出来，让用户使用后提出下一步需求；逐步走向 LLM 还原和 unidbg 差分，不把完整系统作为第一次交付。

- 每次开始前写清本次新增行为和验收例子，只实现这个范围。
- 每次交付提供可复现的 Skill 聊天用语、真实样本、浏览地址、操作步骤和实际验证结果；底层命令留作开发排查资料，不要求用户手动执行。
- 交付后停在可运行状态，用户可直接介入；不自动接着开发后续版本。
- 下一步根据用户反馈重新选定，需求变化时允许调整顺序或放弃尚未实现的方案。
- 只实现本次需要的数据字段、接口和文件。等确有使用场景再拆模块或补抽象。
- 原有功能持续可用；验证以实际行为为主，不为简单页面堆积测试设施。

P0/P1/P2 是长期需求分组，不是需要一次完成的交付包。没有必要实现全部 P0，才让用户打开第一个页面。

## V0.1：能看到函数和原始汇编

**用户目标：通过 Skill 聊天说“用 LightRE 打开这个目录”，由 Agent 启动 Web；用户在页面找到一个函数，点击查看它的地址和汇编。做到这里就交付。**

### 页面与操作

一个页面，两栏：

```text
样本名称                                 已识别函数数量
┌──────────────────────┬──────────────────────────────┐
│ 名称 / RVA 搜索       │ 选中函数的名称、RVA            │
│                      │                              │
│ 0x1640c  fn_0001640c  │ 原始 ARM64 汇编               │
│ 0x1c07c  fn_0001c07c  │ 地址    指令    操作数          │
│ ……                   │ ……                           │
│                      │ 继续加载                     │
└──────────────────────┴──────────────────────────────┘
```

- 列表显示实际已识别函数的名称和 RVA，标明“已识别”，不宣称已发现全部函数。
- 同一个输入框按名称或十六进制 RVA 筛选列表。
- 点击函数后，在右侧显示对应原始汇编，并高亮当前选择。
- 巨型函数按段加载，例如先显示 200 条指令，再继续读取；不能一次把所有函数汇编传给浏览器。分段仅为阅读，不引入基本块视图。
- 页面显示当前加载、空列表或读取失败状态；某个函数失败后仍能选择其他函数。

这一版直接展示真实原始汇编，没有伪代码时也有完整可用的阅读体验。

### 最小实现范围

一个 Python Web 进程，使用 FastAPI 和普通 HTML/CSS/JavaScript。一个页面、读取函数列表和读取选定函数汇编的接口即可；读取逻辑作为普通 Python 函数供页面接口调用。

同时提供一份随项目保存的最小 Skill 说明，让 Agent 知道如何从目录确定目标、调用读取能力、启动页面并返回地址。Skill 直接由当前 Agent 执行这些步骤，不额外启动一个 LLM 会话或调度服务。开发验证时可显式让 Agent 读取项目中的 Skill 说明，不把全局安装作为使用前提。

Workspace 按用户指定或当前上下文动态创建在可见位置，并返回完整路径；分析产物从首版就与 LightRE 工具代码分开。首版只需定位或创建当前 SO 的最少目录和所需文件，不为此预建完整 SQLite。长期布局保持每 SO 一套独立 SQLite 和知识、外层共享 harness；多版本管理与公共知识提炼后续逐项加入。

以已经取得的函数地址、名称和汇编为输入接通页面。缺少结果时由独立分析入口调用 Rizin 并先保存，随后 Web 从 workspace 的 SQLite 只读加载。函数枚举和地址换算沿用统一的 RVA 约定，网页点击不调用分析工具。

先服务一个由 Agent 确定的 SO，不做页面上传、多工作区管理、完整 SQLite 建表、全局 Skill 安装流程、Ghidra 反编译、自动 LLM 还原、unidbg、评论任务、版本管理或自动刷新。后续用到时逐项加入，不预留空实现。

源码布局只需一个薄启动入口、少量读取逻辑和一个页面；具体文件名随实现确定，不先建设分层框架。首版不新增 JSON bundle、缓存或临时持久化格式，避免随后再维护一套迁移。

### 交付时的聊天启动例子

以下是 V0.1 要实际跑通的日常入口，不要求用户输入 Python 命令或 host/port 参数：

```text
用 LightRE 打开 /work2/dg-samples/dC6BDAE，展示函数和汇编。
```

开发期间尚未安装 Skill 时，可显式指定项目：

```text
读取 /work2/LightRE 中的 LightRE Skill，打开 /work2/dg-samples/dC6BDAE，展示函数和汇编。
```

Agent 负责识别目标 SO、准备本次必需依赖、调用读取能力、启动或复用对应 Web，并检查页面可访问后返回实际 URL。目录中只有一个明确目标时直接继续，有多个无法区分的候选时才询问。用户也可直接给 SO 路径。

用户也可补充“workspace 放在某个目录”，或要求把新版本放入已有 workspace。未指定时放在会话当前工作目录下（本环境 `/work2`），避免工具与样本 Git 仓库，Agent 明确报告实际路径。扫描目录排除生成的分析目录，避免将候选与原始副本再次当作新输入。

监听地址、端口和启动参数由 Agent 按环境处理；容器需要的宿主机端口映射在运行说明中交代，映射未就绪时说明具体缺口。无桌面浏览器时返回可访问地址。样本与项目路径均从本次请求解析，示例路径不能写死在代码中，从项目外发起也应可用。

底层保留一个简单的 Python 启动函数或薄脚本供 Agent 调用，实际启动方式随交付记录，便于复现和排查；它不是用户的日常入口。首版不要求用户安装完整远期分析工具链才能看汇编。

### 现场验收

1. 发出上述聊天请求，Agent 完成目标识别和 Web 启动，返回实际外部 workspace 路径与可访问 URL；用户无需补写终端命令或端口参数，工具仓库中不产生样本分析数据。
2. 打开页面看到函数列表、样本名称和已识别数量；列表与本次函数数据来源一致。
3. 搜索一个实际存在的名称片段或 RVA，筛选结果正确，清空搜索后恢复列表。
4. 点击一个短函数，核对右侧地址和汇编与原始读取结果一致。
5. 查看巨型函数，例如已识别的 `0x1c07c`，首段可读，继续加载能显示后续指令，页面仍可选择其他函数。
6. 停止服务后，新会话重复同一聊天请求，仍可启动并浏览该样本；无需依赖前一个 Agent 的内存。

验收通过即完成 V0.1。记录暂时的限制和用户反馈，不顺手扩展到完整浏览器。

### V0.1 验收期间调整：先导出分析结果，再用 Web 浏览

这是用户确定的下一小步，优先于生成候选代码。独立分析入口先调用 Rizin，持久化函数列表及完整汇编；Web 只接受已完成的 SO 分析目录，打开、搜索和滚动均只读取结果。`analysis.py` 中的职责拆入 `src/analyzers/rizin.py` 和 `src/workspace.py`。

验收：先导出真实 SO，随后只提供 SQLite、禁止子进程调用，Web 仍可浏览函数和长汇编；再次导出原子替换旧结果，失败不会留下半份新数据。当前用法与验证见 [V0.1](milestones/v0.1/USAGE.md)。

## V0.2：展示单函数还原候选（已确认，尚未实现）

下一步只打通“现有汇编 → Agent 编写候选 C 代码 → 文件保存 → Web 查看 → 人工反馈 → Agent 修改 → 刷新”。以一个约 10–50 条指令的简单函数验收。

范围、三个功能及人工验收步骤统一维护在 [V0.2 milestone 计划](milestones/v0.2/PLAN.md)。SQLite 沿用原始函数索引，候选正文只存文件；页面展示同一份正文并标明未验证。本轮先做一对一 RVA 关联，保持 V0.1 原始汇编浏览可用。

## 后续增量：每次只选其中一项

下表是可选路线，不是一次开发的清单。若某项仍过大，先拆到一个可演示的入口。

| 增量 | 最小可运行与验收例子 |
| --- | --- |
| 重新打开工作区 | 关闭再启动，从同一工作区读回一个函数及其候选；按实际需要引入最少 SQLite 记录 |
| 候选历史 | 为同一函数保存第二个不可变版本，页面可切换两份代码 |
| 知识与 Unknown | 保存一个函数的理解和未解决项，新会话能读回，页面可展开查看 |
| 跨版本公共知识 | 从已分析版本提炼一个有来源和适用条件的规律，用它设计新版本实验；新结果保存回新版本，公共总结据此更新，不继承旧版本的通过状态 |
| 一次原始运行 | 为一个样本建立可重复的 unidbg 入口，执行一次，保存输入、harness 和真实输出；JNI 缺口也有可续做记录 |
| 一条 Evidence | 将一次有用观察登记并关联函数，页面可定位原始 Run；失败观察同样能保存 |
| 候选构建与执行 | 一个候选编译为 ARM64 SO，在独立 unidbg 实例中执行一个固定用例，保存构建和运行结果 |
| 一次函数差分 | 同一用例双边执行，比较声明的返回值与输出，能展示一处真实差异或范围内通过 |
| 一个反例回归 | 固定失败用例，修复后重跑；新的错误候选不能沿用旧通过状态 |
| 保存 Web 评论 | 对选定函数提交一条评论，生成可重新读取的本地 task Markdown |
| 执行评论任务 | 页面启动一个任务并显示状态，Agent 更新该函数结果后可读取；先把一次任务跑通 |
| 自动刷新 | Agent 发布一个新结果后，页面自动展示并保持阅读位置 |
| 多轮调查 | 一个评论任务内连续调查、实验、修正与比较，保存停止原因及未解决项 |

Ghidra 参考伪代码、调用导航、组合验证、符号执行等按真实调查需要再插入，不成为首版的前置条件。自动化逐步覆盖已经跑通的操作，不先建设完整策略或调度平台。

## 每次交付的最少记录

每次只报告：本次能做什么、可复现的聊天请求与实际 URL、一个真实操作例子、实际验证结果，以及本次尚未覆盖的范围。底层启动资料保留供 Agent 排查。提供可运行结果后留给用户体验，不自动继续实现整条路线。

实现计划随着体验反馈更新。需求清单保留长期条目，未做到的条目保持未验收，不为某个小版本宣布整个系统完成。
