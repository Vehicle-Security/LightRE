# VM 语义恢复里程碑

状态：单个 VM 样本的分析路线，尚未实现或验收。本文将 VM 还原拆成可独立检查的能力，不对应新的产品版本，也不要求用户逐阶段批准运行。目标范围以一个 SO 的选定逻辑入口为起点，按 [Goal Loop](GOAL_LOOP.md) 自主续做；现有静态候选流程尚不具备下述动态和求解能力。[V0.31](milestones/v0.31/PLAN.md) 先建立固定测试 SO 的 harness 与最小修复循环，该测试 SO 不含 VM，通过不代表完成这里的 M0。

本文只维护单个样本的分析阶段与完成依据。工具开发顺序见 [路线图](IMPLEMENTATION_PLAN.md)，双边执行与分段比较见 [动态差分设计](DIFFERENTIAL_EXECUTION.md)；与产品版本的关系见 [文档入口](README.md)。

## 推进方式

主线是：可重放入口 → 取指 → 解码 → dispatch → 指令语义 → 逻辑控制流 → 业务源码。每阶段都要能预测某种尚未用于建立模型的行为，再由原实现检查，不能只给已经发生的 trace 补标签。

这些是能力里程碑，不是对所有 VM 结构的假定。取指、解码和分派可能交错或融合；可能有多个分派器、直接线程化、变长指令、动态密钥或自修改字节码。允许联合调查相邻阶段，再分别说明已验证能力及依赖，不强行寻找单一取指函数、显式 VPC 或 opcode 表。

OLLVM 和 MBA 贯穿各阶段。每次只处理阻碍当前目标的控制和数据切片，例如先恢复下一次取指地址，不先清理整个解释器。化简保存机器位宽、前提和检查结果；路径前提下成立的结论不能推广为全局结论。强制实验与自然执行分开记录，强制走过一条路径不能证明它自然可达。

## M0：选定入口可重放，并找到虚拟化边界

**要回答：从哪个真实入口、什么初始化与输入，可以进入目标 VM 并观察返回或明确停止点？**

- 建立最小 unidbg harness，完成该入口必需的依赖和初始化；有 JNI 依赖时才补齐，纯 C 入口不强加 JNI。明确真实输入与实验环境假设。
- 识别候选 VM 进入和退出位置、原生参数如何进入虚拟状态、返回值及相关副作用如何离开。VM 上下文可以先不完整，不能只因看到循环就认定已找到解释器。
- 保存一次可重放 Run：目标与资源来源、harness、输入、环境、地址换算、输出和原始日志。每次重放从含义一致的初态开始，明确控制或比较非确定性来源。

**完成条件：** 从保存材料重新运行可以复现选定入口的相关观察，且 VM 边界判断有状态或数据流依据。只加载成功、只执行到 JNI_OnLoad，或依赖未说明的固定返回值不能算完成。

## M1：识别并预测取指

**要回答：下一条虚拟指令的信息从哪里读取，位置如何变化？**

- 从实际执行的读取向前追踪地址来源，识别字节码资源或运行时生成区域、逻辑位置及其原生表示，记录读取宽度和位置更新。区分指令流、普通数据和 native dispatcher 状态。
- 无需先理解所有 handler；先解释选定路径连续虚拟步骤的指令读取。逻辑 VPC 可对应指针、偏移、多个值或隐含状态，不要求存在单独变量。
- 对阻碍地址计算的 MBA、平坦化或解密代码做局部切片；运行时生成或修改的字节码保存实际读取版本及来源，不能只引用原始文件字节。

**产物与检查：** 给定步骤开始状态，预测读取地址、宽度和字节，与另一次原实现执行的实际读取核对。记录 VPC 的原生来源及下一位置的已知条件；分支 handler 的目标尚未解析时显式保留未知。

**完成条件：** 对声明的路径或指令范围能够重复识别取指事件并预测其来源，且证据区分了正常数据读取。只找到一次 `ldrb` 或递增指针不能算完成。

## M2：恢复解码与长度规则

**要回答：取到的内容如何成为指令类别、操作数及后续取指所需状态？**

- 恢复选定指令形式的字段、宽度、端序、符号扩展及长度；如存在滚动密钥、上下文相关编码、解密缓存或隐式操作数，将它们作为解码输入与输出。
- 不要求此时知道指令的业务名称，可以使用中性类别。字段含义尚未确定时保存位置和数值，不提前叫作寄存器编号或跳转偏移。
- 构造可执行的局部解码模型，并保存依赖的状态。处理变长或融合指令时不强行采用固定步长。

**产物与检查：** 在未用于建立模型的实际指令实例或可达解码状态上，将模型的类别、操作数、长度及相关状态更新与原实现对齐。不能用 trace 中的已知解码结果作为模型输入。

**完成条件：** 声明范围内可以独立解码，尚未支持的编码或状态明确报告为未知，不退回固定长度、固定 key 等猜测。

### M2 的条件分支：滚动密钥与历史相关解码

这是必须能够调查和兼容的潜在机制，目前没有样本分析证据确认。不能预设存在密钥、固定 XOR 算法、单个密钥变量或逐条更新；直接编码、固定变换和历史相关解码分别依据证据判断。所谓“密钥状态”也可能是分散在多个寄存器或内存位置的解码状态，不代表密码学意义上的密钥。

先从实际指令读取向解码结果追踪依赖，检查是否存在跨虚拟步骤保留并更新的状态，以及它是否真正影响解码。一次 trace 中数值同时变化只能形成线索；结合静态依赖和不同可达状态的观测判断。无法排除状态依赖时标记未知，不能因当前样本解码成功便认定仅依赖字节码。

| 子目标 | 需要得到的能力 | 检查依据 |
| --- | --- | --- |
| M2a 状态来源 | 若有状态依赖，定位初值来源、重置位置及真实依赖的最小状态 | 从保存的初始化与输入重放，核对首个相关解码边界的状态；不把一次捕获的 key 当作所有运行的常量 |
| M2b 更新关系 | 恢复状态在取指、解码、handler 或控制转移中的更新及先后顺序 | 保存相关位置的更新前后值，核对位宽、字节消耗及实际依赖；对 MBA 按需局部化简和检查 |
| M2c 连续预测 | 从一段开始的有效状态连续预测解码和后续状态 | 在未用于建模的自然运行片段检查连续多步；不能每步从原 trace 注入下一状态来掩盖模型错误 |
| M2d 控制转移衔接 | 若目标含分支、循环、调用或返回，解释转移后的解码状态如何取得 | 在可达路径核对是否存在继承、重置、保存恢复或其他更新；未遇到的机制不预设存在 |

出现解码差异时定位首次状态或输出分歧，保留反例；不要跳过异常字节、猜一条看似合理的 opcode，或任意换 key 继续。可先从已知有效初始化重放得到前态，再调查局部规则，不要求先解出全局闭式公式，也不假定 unidbg 提供完整快照。

没有状态依赖证据时保留简单解码模型及其已检查范围，以上子目标无需凭空制造；证据不足时仍明确列出未排除的依赖。该条件分支调查结果同样影响后续阶段：

- **M1/M3：** 取指来源和 dispatch 模型按实际依赖接收必要状态，不能默认字节码偏移或 opcode 单独决定结果。
- **M4：** 指令的前后态检查包含相关解码状态更新，覆盖 handler 可能承担的更新；不要把它当作无用变量删掉。
- **M5：** 同一 VPC 下若未来解码依赖的状态不同，不能直接合并逻辑节点，也不能仅按 VPC 缓存解码结果。先按已识别依赖区分上下文，证明等价后再合并，不盲目复制整份机器状态造成图膨胀。
- **强制探索与重放：** 不能只改 VPC 或原生 PC 就假定进入了有效路径。检查相关状态、字节码版本及执行阶段是否相容；相容状态可由自然运行、重放或有依据的构造取得，仍需记录干预，不能据此证明自然可达。

## M3：恢复 dispatch 关系

**要回答：给定已解码指令及必要 VM 状态，实际会执行哪段原生实现？**

- 定位实际控制转移机制：表索引、比较链、计算跳转、多级分派或直接线程化。区分 VM 指令分派与平坦化状态机；二者可能嵌套。
- 从实际跳转目标反向切片，恢复目标计算及条件，化简相关 MBA。记录类别或 opcode、上下文条件与 handler 入口/片段之间的关系，而非假定一 opcode 对应一函数。
- 自然执行用于检查目标预测；强制探索用于调查候选区域并记录相容前态。对未观察到的映射，可用静态依据和求解补充，但需保留结论范围。

**产物与检查：** 可执行或可计算的 dispatch 模型，以及每个目标的来源和条件。在未参与建模的实例上预测目标，与原实现实际转移核对；只按 opcode 索引保存过的 trace 不算模型。

**完成条件：** 选定入口已覆盖的指令类别与声明上下文内，目标预测得到检查；未解关系仍保留未知。不要求先枚举整个 VM 的全部 handler，也不能将已观察目标表称为完整映射。

## M4：恢复一组可组合的虚拟指令语义

**要回答：一次虚拟步骤对寄存器、栈、内存、标志、VPC 和外部状态做了什么？**

- 从当前入口实际需要的指令开始，恢复可组合的状态模型；先覆盖输入到输出依赖上的关键指令，再扩展，不按 opcode 数量凑进度。
- 处理 handler 内部的 OLLVM 与 MBA，提取真正的状态转移。指令可跨原生片段，也可能融合多个操作，不能强行逐函数恢复。
- 保存访问宽度、别名、异常/退出及相关外部调用。需要捕获局部前后态时优先从自然运行边界观测，不假定 unidbg 自动支持完整快照恢复或任意 handler 独立调用。

**产物与检查：** 将局部语义模型从捕获的前态执行，与原实现的后态及相关副作用比较；使用不同操作数和可达状态验证，并检查相邻多步组合。SMT 可证明局部纯表达式的等价，但不能覆盖未建模的内存或调用。

**完成条件：** 声明指令组能够组合解释选定片段，前后态差异及未知写入明确。仅凭一次输入给 handler 起名 `ADD`、`LOAD` 不能算完成。

## M5：恢复虚拟程序的逻辑控制流

**要回答：字节码实际表达哪些基本块、分支、循环、调用与退出？**

- 在解码和指令语义基础上，从选定入口构建逻辑 CFG，恢复分支条件、目标及必要调用关系。节点使用字节码来源、逻辑位置及必要解码上下文，不能只按原生 handler 地址合并。
- 消除仅为混淆服务的状态跳转与谓词，但保留必要算法状态。对仍受 MBA 隐藏的条件继续做切片、化简与输入构造。
- 将自然观察到的边、仅强制探索的边、静态/求解支持的边及未解析边区分。融合指令、多入口或上下文相关解码需要反映在图的含义中。

**产物与检查：** 逻辑 CFG、边条件及来源。通过不同输入检查预测路径；在目标存在条件分支或循环时，覆盖相关分支方向和代表性的循环退出，保留无法覆盖的依据和后续探测条件。

**完成条件：** 选定范围内的关键控制流有解释和验证，未解析控制转移可定位。覆盖了当前 trace 不等于 CFG 完整，不删除仅因尚未运行到的边。

## M6：交付去虚拟化业务源码

**要回答：能否脱离原 VM，直接实现该入口的业务行为？**

- 将已恢复指令语义与逻辑 CFG 组织成普通运算、数据结构及分支，整理类型、函数、文件与命名。中间的解码器、dispatch 模型和解释器可用于调查，但不作为最终业务还原的替代品。
- 构建独立候选，以含义一致的输入、状态和环境与原实现分别执行，比较返回、输出、相关持久状态和声明副作用，重跑累计反例及多步组合用例。
- 导出可独立构建与调用的源码，保留原生入口、字节码来源、版本和验证范围。未覆盖的其他入口或指令继续明确留在范围外，不能悄悄缩小原始任务。

**完成条件：** 选定交付范围内得到直接表达业务逻辑的源码，构建与行为检查通过，影响该范围的未知语义已解决。调用原 SO 代算、复制 VM 分派循环或只匹配少量固定输出不算完成；有限用例也不等于全输入形式证明。

## 给外层循环与 Prompt 的约定

每轮原始任务和上下文引用本路线，说明当前目标阶段、适用入口/路径/状态、已有模型及证据、待解释差异与本轮检查方式。轮次不是里程碑：一个阶段可运行多轮，也可在一轮解决相邻阶段的相互依赖。

阶段推进由实际产物和检查依据决定；新反例可以使先前结论回到待修正状态。复用现有任务记录、Run、Knowledge 和版本引用，不新增一套阶段数据库或通用策略引擎。阶段记录属于分析进展，不替代任务完成条件和产品人工验收。

在 V0.31 的 harness 基础之后，选择一个真实 VM 入口打通 M0–M3，并尽早选择一个短片段贯穿 M4–M6，取得业务行为闭环；这些不是 V0.31 的验收条件，也不等全部 opcode 恢复后才开始差分。之后扩展同一入口的剩余指令和路径，再以新入口验证方法的适用范围。开发过程的小步交付不意味着成熟工具运行时需要用户逐阶段确认。

工具开发阶段与本文件的分析阶段分开，见 [能力引入时机](IMPLEMENTATION_PLAN.md#v02-之后的能力引入时机)：原实现可重放后开始输入 fuzz，有可执行候选即开始行为差分；M1–M3 按具体疑点使用定点观测与受控强制执行；部分 M2–M3 规则明确后对该范围做结构化字节码 fuzz，M4 的局部语义模型可作为相同变异程序的比较对象。差分和强制探索都无需等待全 VM 恢复，滚动状态与前态相容性仍按前述约束处理。
