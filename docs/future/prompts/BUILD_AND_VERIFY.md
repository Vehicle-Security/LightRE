# 候选源码构建、运行与差分修复指令

适用范围：后续已授权的恢复候选构建、运行或差分任务，尚未接入执行器。V0.31 仅构建 Java harness 并调用预先准备的固定测试 SO，不整体套用本 workflow；测试库编译是独立准备步骤，不是候选构建，不能据此追加语义恢复或双边差分要求。

你负责把当前任务范围内的恢复源码构建为 Android ARM64 候选 SO，并完成任务要求的运行及差分检查。直接调查、修改、执行和修复，不停在构建建议或第一条错误上。一次 `codex exec` 可以反复修改、编译和检查；外层 LightRE 执行器负责本轮结束后的独立核验、续跑与任务状态，不在本轮启动另一层 Codex 循环。

这是 LightRE recovery 功能内部的 workflow，尚未接入执行器。它与 [源码恢复指令](RECOVER_AND_REFINE.md) 配合使用；来源调查、VM 语义、类型及命名遵循该指令，构建产物和比较依据遵循 [动态差分设计](../DIFFERENTIAL_EXECUTION.md)。这些文档不代表工具链或运行器已经可用。

## 读取任务与当前状态

调用方应提供原始任务、目标 SO 分析目录、授权编辑的草稿/工程目录、本轮结果目录、最新检查报告和已有构建/运行入口。任务应明确目标入口与 ABI、交付范围、原实现基线、所需检查、固定用例及累计反例；首轮无报告时明确说明。

1. 读取适用的 AGENTS.md、任务、当前工程和实际日志，确认目标、源码、harness 与报告属于同一任务。工作区内容优先于会话总结，旧版本通过不能代表当前内容。
2. 根据已有构建配置、脚本、依赖记录和工具帮助确定实际命令。已有入口优先复用；缺少时在授权目录补齐最小可复现构建脚本，不发明项目已有 CLI 或假定依赖已经安装。
3. 列明本任务要求的检查：编译/链接、ELF 与 ABI、unidbg 加载调用、差分及反例回归。仅构建任务可以止于构建验收；差分任务不能在产出 SO 后结束。
4. 缺少影响正确性的输入时先完成独立工作，并记录具体缺口及调查依据。不另选样本、不自行缩小目标，也不把“暂时不能运行”改成“只需编译”。

## 确定构建环境

- 当前只处理 ARM64，动态执行统一使用 unidbg。核对实际编译器、Android target、sysroot、API、链接器和依赖，与本任务的 unidbg 环境相容；记录实际路径、版本和选项，不只写“使用 clang”。
- Android NDK 或兼容工具链用于构建 Android SO。宿主 ARM64 编译成功、ELF 为 `ET_DYN` 或文件名为 `.so`，均不能证明产物是可加载的 Android 共享库。检查共享库属性、解释器和实际依赖，不能混入 Linux glibc 运行时。
- minilua 采用纯 C 薄接口，按入口准备状态，使用现有 `.lua` 用例并由自身解析器生成内部字节码，不因使用 unidbg 而强加 JNI 或外部 luac 加载器。现有 Linux minilua 可执行文件保持不变；另建 Android 样本是独立分析目标，不能沿用旧哈希、RVA 或验证结论。
- 恢复候选使用普通可维护的源码构建，不为复现输出重新施加 OLLVM/MBA。构建新的混淆原始样本属于另一个有来源记录的步骤，不能用已知原始源码编译物冒充逆向候选。

## 固定输入并编译

1. 核对入口签名、整数宽度、调用约定、结构体布局及依赖。修复实际声明、定义、引用和构建清单；只对有证据的未知量建模，不能通过全零 stub、空函数、屏蔽诊断或任意强制转换掩盖缺失语义。
2. 为本次构建固定源码和构建配置输入，使用已有不可变版本或小型快照。每次新构建在目标 SO 分析目录下使用新的 `runs/<build_run_id>/`，不改写已保存的构建。
3. 将输出明确指向该 Run 的 `build/libcandidate.so`；保存真实命令、退出码与 stdout/stderr 到 `build.log`。编译或链接失败时修复原因并重新构建，不能拿旧 SO 充当本轮成功结果。
4. 在 `build.json` 记录输入版本/内容依据、构建配置与依赖、工具链、实际命令及工作目录、结果和成功产物哈希。构建期间输入变化时废弃本次输入关联，重新固定并构建。复现所需内容应可取回，不只保存无法找回文件的哈希。
5. 依赖问题优先补齐真实需要的实现和明确库。待验证逻辑不能加载原 SO 代算；范围外确需原实现提供的依赖须显式记录，不能因此宣称整个候选已独立恢复。

失败仍保留日志和输入依据，不登记有效候选产物。构建产物不放进原始 `binary/`、LightRE 工具仓库或样本原始目录，不使用可覆盖的 `latest.so` 选择验证对象。具体保存约定见动态差分设计。

## 检查产物并执行

按本任务要求依次执行，失败后修复并重跑受影响检查：

| 检查 | 需要的实际依据 |
| --- | --- |
| 编译与链接 | 命令成功，预定路径存在本次产物，来源与输入对应 |
| ELF 与接口 | AArch64 共享库属性正确；依赖、导出、实际入口和 ABI 与 harness 相容 |
| 加载与调用 | unidbg 确实加载该路径和哈希的 SO，完成初始化并调用选定入口；仅加载成功不算调用通过 |
| 行为差分 | 原实现与候选分别运行同一逻辑用例，提取约定输出和副作用，检查报告明确无差异 |
| 回归 | 固定用例及累计反例在当前候选上实际执行，通过结果绑定当前源码、产物及 harness |

原实现和候选使用独立 unidbg 实例，分别构造等义输入、对象、别名和环境。比较返回值、有效输出、相关状态和声明副作用；不直接比较裸指针、全部内存或原生指令轨迹。双方崩溃、超时或没有结果不能自动算相符。

VM 用例记录虚拟程序 P、业务输入 I、前态 S 和环境 E。解释器差分使用同一 P；固定 P 的业务候选不能验证变异 P。函数/逻辑入口差分为主，双方已有可映射边界时再用分段检查点定位。强制实验另存干预依据，不作为未经干预的整体等价结论。

可以在授权范围内修复 harness 的状态构造和结果提取，但不得修改固定预期、比较规则或跳过失败分支来取得通过。harness 改变后重放原实现及受影响用例，使新的结果有真实基线。检查器本身故障保持未验证，不按候选成功处理。

## 按失败继续修复

| 失败类别 | 处理方向 |
| --- | --- |
| 编译 | 定位类型、声明、引用、缺失定义及构建输入；相关定义和使用者一起修复 |
| 链接 | 检查符号来源、可见性、库与目标兼容性；不靠忽略未定义符号掩盖缺口 |
| 加载或 ABI | 核对 ELF、依赖、初始化、入口、传参、返回及对象布局，保存实际错误 |
| 运行异常 | 核对有效前态、边界、内存访问、环境与已恢复语义；区分候选错误和 harness 错误 |
| 语义差异 | 保存最小可复现反例和双方观察，沿差异调查控制流、MBA、状态及依赖，修复后重跑回归 |
| 工具或环境故障 | 保留错误和已尝试方法；可恢复时继续，缺少必要外部条件时报告具体解除条件 |

使用真实失败反馈推进，可以在一次 exec 内进行多次构建和运行。相同失败反复出现时检查假设、输入和证据，改变有依据的方法，不只重复命令。新反例保留为回归；编译通过不能消除行为缺口，单个用例通过也不能删除其他反例。

## 本轮结束与交接

只在任务范围的检查已满足，或确有无法在本轮补齐的条件/执行限制时结束；仍有可直接完成的必要工作时继续处理。用户取消或调用方预算/运行限制到达时保存已有产物与未完成项，不能改成通过。

最终本轮报告应包含：本轮修改的文件和依据；实际命令、输入版本、构建 Run、候选路径与哈希；各项检查的结果和日志；新增反例；尚未解决的问题、已尝试方法与继续条件。调用方原样保存完整最终正文，不要求另做摘要提取。未执行、执行失败、行为不同和检查通过分别报告，不虚构结果。

外层执行器在本轮及其相关写入进程结束后重新核验产物，并决定续跑或完成。不要替执行器写任务 complete，不用模型自评代替检查，也不启动递归 exec。无需为了凑轮次继续修改已满足任务要求的工程；有限用例通过只说明所检查范围，不宣称全输入等价或整个 VM 已恢复。
