# 去混淆工具链：分支触发、控制流平坦化与 MBA

状态：规划中。目标定位：LightRE 的最终产品是逆向还原（恢复业务源码），
unidbg 补环境只是执行观测层（L1）；控制流平坦化与 MBA 是主要分析障碍，
对应 [VM_RECOVERY](VM_RECOVERY.md) M1-M5 的工具支撑缺口。

## 能力栈与缺口

| 层 | 能力 | 状态 |
| --- | --- | --- |
| L0 静态候选 | Recovery 函数级 C 源码 | V0.2 已交付 |
| L1 执行观测 | unidbg harness、定点记录、hook | V0.3 收尾 |
| L2 分支探索 | fuzz / 强制执行 | V0.4（本文"分支触发"节） |
| L3 切片 | P-code 导出、反向切片、位向量表达式提取 | **缺口**：VM_RECOVERY 明确"P-code 尚未接入" |
| L4 求解 | SMT 等价检查、MBA 化简管线、局部约束求解 | **缺口**：无 z3 接入 |
| L5 结构恢复 | dispatcher/状态存储识别、逻辑 CFG、去平坦化 | **缺口**：仅分析方法，无工具 |
| L6 业务交付 | 候选构建、双边差分、去虚拟化源码 | 差分已设计（DIFFERENTIAL_EXECUTION），V0.4 起接入 |

## 新增功能规划

### F0：分支触发——字节码 Fuzz 与强制执行（L2，V0.4）

前置：V0.3.5 的终态判定改造（缺口清零才算 observed）与探索运行标记
（`mode=probe/fuzz` 不算通过）。对 VM 类保护（字节码由 SO 内解释器执行），
系统性触发分支，使"环境完整"从单条路径升级为被触发分支空间。

三种手段（成本递增，组合使用）：

| 手段 | 原理 | 适用 |
| --- | --- | --- |
| 字节码 fuzz | 变异输入字节码，按覆盖率保留变异 | 实现简单，先跑 |
| 强制执行 | unidbg hook 分支点，强制翻转条件后两侧都执行 | VM 解释器分支集中在 dispatch loop，定向高效，优先实现 |
| concolic | 真实运行收集分支条件 → 翻转重跑 → 逐步扩路径 | 完整符号执行（VM_RECOVERY M0-M6）的轻量替代 |

停机准则：缺口清单为空，且覆盖饱和（连续 N 次变异/翻转不再触发新分支）或达到预算。
与 DIFFERENTIAL_EXECUTION 互补：fuzz 生成输入，差分比对双边输出语义。

### F1：Ghidra P-code 导出与反向切片（L3，V0.5 前置）

- 新 analyzer：函数级 P-code/SSA 导出（定义-使用链、内存依赖），进 index.sqlite
- 反向切片服务：以"状态更新 / 分支条件 / 计算跳转目标"为终点的切片查询
- 表达式提取：固定宽度位向量表达式，保留 ARM64 W/X 宽度、截断、NZCV 语义
- 产物供 M1-M3（取指/解码/dispatch 切片）与 MBA 管线共用

### F2：SMT 求解与 MBA 化简管线（L4）

- z3 接入：位向量等价检查（SAT 保存反例，UNSAT 仅在模型与前提内证明等价）
- MBA 管线：常量传播/规则化简 → 线性 MBA 规范化 → 候选（规则+LLM）→ SMT 检查 → 反例回填
- 局部约束求解：对分支条件求满足输入，辅助自然可达探索（区别于强制执行）
- 优先化简影响分派状态、分支条件、内存地址、外部输出的表达式

### F3：平坦化结构恢复（L5）

- dispatcher 与状态存储识别：多轮运行的读写/转移统计定位，区分 VM 分派与平坦化状态机
- 逻辑边恢复：`A → dispatcher → B` 整理为逻辑边，保留沿途有效状态更新
- 逻辑 CFG 构建（M5）：区分自然观察边 / 强制探索边 / 求解支持边 / 未解析边
- 去平坦化输出：逻辑 CFG 到候选源码的映射，不直接 patch 原始 SO

### 排期（嵌入选定的 D1-D4 能力顺序）

| 版本 | 功能 | 支撑 |
| --- | --- | --- |
| V0.4 | 差分闭环（候选构建+双边差分）+ F0 分支触发 | D1/D2/D3；L2 完整 |
| V0.5 | F1 切片 + F2 SMT/MBA | D2 的工具底座 |
| V0.6 | F3 平坦化结构恢复 + M4-M6 贯通 | D4 |

依赖关系：F1 先于 F2（表达式来源）；F1/F2 先于 F3（化简暴露真实后继，二者互反馈）；
F0 分支探索与 F1 并行推进，互不阻塞；F0 依赖 V0.3.5 的探索运行标记机制。

## 边界

- 不先建设通用去混淆器或全程序符号执行；围绕关键切片（取指地址、分派目标、分支条件）处理
- 强制走过/求解支持的边与自然可达边永久区分记录；不据此删除分支
- LLM 提候选、求解器做检查；不以多次调用 LLM 或润色伪代码代替这些能力
