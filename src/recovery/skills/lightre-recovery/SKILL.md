# 函数恢复与修改

先理解任务内嵌的源码、知识、汇编及用户意见。首轮和指定函数重跑主动改善可读性；评论只完成该条意见，材料足够时直接处理，避免重做无关调查。执行时的当前源码是修改基线，reviewed_snapshot 只用于理解用户当时看到的内容。

## 命名、类型与语法

沿参数、返回值、调用和内存访问追踪数据流。主动为 FUN_、fcn_、param_、uVar、local_ 等临时名称恢复用途；业务证据不足时用 input_buffer、byte_count、cursor、state 等角色名，不暗示未经证实的算法或业务。保留已有准确名称及已知导出 ABI 名称，notes 说明关键推断依据。

在证据支持时恢复指针、整数宽度/符号、长度、布尔、返回值和结构字段，把 CONCAT/SUB/扩展等 Ghidra 伪运算写成明确 C 表达式。核对截断、符号扩展、移位、浮点/整数重解释与访问宽度；不能把位拼接误写成数值加法，或把按位取反误写成逻辑取反。

去掉能证明冗余的临时变量、转换和分支，清晰表达循环与错误路径；保留调用及求值顺序、内存副作用、volatile、溢出与 ABI。未理解的状态机、goto、MBA 和低层类型保留并解释，不因局部复杂就放弃其他有依据的改进，也不补造空函数、固定返回、helper 或省略号。

## 改名与返回前检查

函数身份由 RVA/源码 ID 保存，fcn_ 只是临时名。参数、局部变量改名必须同步声明与同一绑定的全部引用，不能只改签名；避免误改同名字段、字符串和其他作用域。函数改名同步递归调用，其他函数的直接调用由 LightRE 收尾按绑定同步；函数指针、头文件原型、宏和无法解析的引用不保证自动处理，不能宣称工程级改名完成。

返回前按顺序应用拟议 edits，核对修改后的声明与使用，不能留下旧名称造成未声明标识符；检查分支覆盖、访问宽度和副作用。补丁使用足够上下文，不能以无差别文本替换代替绑定检查。代码注释和知识同步修正旧名称与结论，保留有效证据、假设和未知项，区分事实与推断。

知识是完整当前分析，不逐轮追加日志；评论的 reply 简述处理结果，不替代知识。只有确实无安全改进或证据不足时才原样保留并说明原因，不能把格式化、注释或空改动称为逻辑恢复。候选未经编译/执行验证，不声称等价。

## 需要机器证据时

只核对具体疑点。仅汇编任务以全部已保存指令为起点，按块追踪控制、数据和调用，不能读取旧 C/Ghidra 伪代码代替分析；旧知识只是线索。已有完整初稿时，保留并指出尚未解决的警告与缺失路径。需要检查 ELF 地址、缺失块、halt_baddata 或特殊 ABI 时读取 [ASSEMBLY.md](references/ASSEMBLY.md)。

源码模块与 Ghidra 分组不代表原始源码模块。仅输出本批指定函数正文，不改路径或边界，不添加 LightRE 标记；函数专用类型加 RVA 前缀以免冲突。知识位于 knowledge.md 的 RVA 二级标题下，按函数 API 读取，内部标题三级及以下。
