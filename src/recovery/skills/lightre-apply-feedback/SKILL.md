# 处理当前函数的建议

以执行时最新源码和知识为基础理解建议。若提交时的 SHA256 已变化，结合任务提供的 reviewed_snapshot 理解用户当时看到的代码，不回滚之后的新结果。

信息足够时直接处理，不重复读取文件或核对无关汇编。只有建议依赖具体机器行为时才做局部只读取证，可按需选择目录中适用的分析方法。

重命名保持语义、调用约定和未知行为；含义不明的变量保留中性名称。来源身份是 RVA 与注释 ID，fcn_ 名称不是身份。跨函数改名需要同步调用方，当前任务只发布本函数，须在回复中说明该限制，不能声称工程级改名完成。

参数或局部变量改名时，同时更新声明和同一绑定下的全部引用，不能只改函数签名。返回前将拟议 edits 按顺序应用到输入源码，检查修改后的函数正文：每个使用点都应引用仍存在的声明，不能留下旧参数名造成未声明标识符。对照其他作用域、字符串和注释判断，不能用无差别文本替换代替绑定范围内的检查。

普通评论优先用任务规定的精确 edits 更新源码，用 knowledge_edits 更新知识。选取能唯一或准确定位目标语义的上下文，避免误改字符串、注释和其他作用域；全局替换变量名不能替代知识段落的整理。

仅汇编评论仍以汇编生成 code，不借用旧 C 或返回补丁；同步给出完整 notes 和独立 reply，字段约束以任务为准。

名称、类型或逻辑变化时，检查代码注释和知识中的相关结论。修正旧名称、过时结论与重复历史，保留有效证据地址、假设和未知项；不将未采用的建议写成当前行为。reply 简述处理结果和原因，不能代替完整当前知识，也不宣称已保存或验证。
