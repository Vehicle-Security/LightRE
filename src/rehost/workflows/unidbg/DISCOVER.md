# 调查原始目标与可调用边界

1. 核对原始 ELF 哈希、AArch64、PT_LOAD、动态依赖、导出及初始化入口。
   先读任务保存的 readelf 原始输出；不足时用现有 Ghidra 导出、objdump、字符串、重定位及调用者补证据。
   不凭 .so 后缀断定 Android 兼容；glibc PIE 不能直接当 Bionic 共享库。
2. 区分原生依赖、APK/DEX、配置、字节码和业务输入。文件存在不等于已进入目标执行逻辑。
   原样使用任务提供的种子，调查读取路径、长度、附带参数与前置状态。
3. 从导出、JNI_OnLoad、RegisterNatives 或静态调用关系定位入口，核对 ARM64 ABI、
   整数位宽、指针/长度、对象生命周期和必要历史调用；未知项写入 HARNESS.md，不能猜几个整数直接跳 RVA。
4. 纯 native 目标不强加 Dalvik/JNI。有 JNI 依赖时调查类/方法/字段、动态注册和实例/静态调用，
   有 APK/DEX 时用作实际证据，不假设 unidbg 会执行任意 Java 实现。
5. 在 HARNESS.md 写出可执行的最小计划：加载顺序、选定入口及依据、输入如何进入、
   如何确认实际原生执行、输出范围与停止点、现有环境假设和待补缺口。

未知目标可能没有足以恢复入口的材料。保留调查与解除条件，不改选已知样本，不复制旧 harness 补答案。
