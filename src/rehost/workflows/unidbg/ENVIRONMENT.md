# 根据真实运行缺口补环境

每次从最早的真实失败入手，保存调用栈、模块+RVA、JNI 签名、参数和原始日志，
先分辨 ABI/初始化错误、缺依赖、缺系统接口、缺 Java 行为与目标自己的异常。
环境问题不能直接当作原算法错误；复杂 MBA 或 VM 分派也不是应当跳过的环境缺口。

- **加载和 libc**：核对 Android/Bionic、API、DT_NEEDED、构造器及版本。仅补实际依赖，
  不改目标机器码、伪造导出或给任意未解析符号统一提供空实现。
- **JNI**：实现实际访问的类、字段、方法和对象状态，保留实例关系与调用顺序。
  未实现时打印完整签名及调用位置并失败。APK 中的类型信息不等于已实现其设备行为。
- **文件/系统接口**：按真实访问实现 IOResolver、系统属性或必要 syscall；数据有资料来源，
  或明确记为本次实验环境假设。记录文件内容依据，所需可重放资源放入 src/main/resources。
- **时间/随机/线程**：保存初始化值、调用历史和相关环境约定；需要确定性时显式固定并说明影响，
  不能悄悄每次换值，或用统一返回零掩盖路径依赖。
- **设备与网络依赖**：缺少真实设备/外部资源时记录具体签名、所需状态和限制。
  可构建明确的条件实验，但不能把自选替身说成真实设备证据或业务语义恢复。

每次补丁更新 HARNESS.md：缺口 → 证据 → 实现或假设 → 真实重跑结果。
补环境只服务于原实现的自然入口运行。强改 PC/VPC、分支、ready 标志或返回值属于干预实验，
需要另行明确授权与记录，不作为本 workflow 的自然运行通过依据。
