## 每次工作顺序

1. 先读本文，再读所选 SO 的 harness.json、原始任务、调用契约、最新实际检查和上一轮完整记录。
2. 核对 binary 路径/哈希、架构、入口 ABI、初始化、资源及参数。已有说明保留并修正，
   不能覆盖重置经验，不能把其他 SO 版本的地址或运行成功套用到本版本。
3. 按实际缺口生成或修复最小 Maven/Java 工程。修复工程前先把适配计划与依据更新到本文；
   未知内容明确记为待确认，不编造签名、环境或结果。
4. 构建并真实调用目标；失败时依据日志继续修复。仅加载 SO、构建成功或模型声明完成都不算通过。
5. 同步本文的入口、输入/输出、初始化、构建运行方法和已知缺口；引用实际检查路径，
   已验证与尚未验证的内容分开写。下方工具检查区由外部执行器维护，保留其标记。

共享工程是唯一可编辑版本。每个 SO 用自己的 harness.json 传入版本参数，运行记录在该 SO 的 runs/。
Run 保存执行前的 HARNESS.md、源码和 pom 副本，历史副本只用于重放，不修改补写。
每次运行后外部执行器更新当前说明的最近检查区；当次结果仍以 Run/任务中的检查记录为准。
